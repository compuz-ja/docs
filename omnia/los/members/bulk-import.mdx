Bulk import creates many member profiles at once from one CSV file. You upload the file, every row is previewed and validated, and you then commit the rows that pass. Nothing is created until you confirm the preview.

<Tip>
  Bulk import is for onboarding an existing book of members, for example from your Core Banking System. For a single new member, use **New member**. See [Creating members](/omnia/los/members/creating-members).
</Tip>

## Who can import members

You need the **Import members** permission, separate from **Create members**. If you do not see **Import** on the Members list, ask your Administrator to check your role.

## Where to start

Open **Members** and click **Import**. The dialog has three steps: upload, preview and result.

## The CSV columns

The file needs a header row. Columns are matched by name, ignoring case, and spaces or hyphens count as underscores, so `first_name` and `First Name` both work. Unrecognised columns are ignored. A CSV saved from Excel imports cleanly.

### Required columns

Every row needs a value in all seven. A file missing one is rejected with the column named, for example `Missing required column "member_since".`

| Column | What it holds |
|---|---|
| `cif` | The member's CIF number from Core Banking. Up to 40 characters. Unique in your workspace and in the file. |
| `cu_account_number` | The Credit Union Member Account Number from Core Banking. Digits only, up to 16. |
| `member_since` | The date the member joined, from Core Banking, as `yyyy-mm-dd`. A real date, not in the future. |
| `first_name` | First name. |
| `last_name` | Last name. |
| `date_of_birth` | As `yyyy-mm-dd`. The member must be at least 18. |
| `branch_code` | The code of a branch that already exists in your workspace. |

### Optional columns

| Column | What it holds |
|---|---|
| `middle_name` | Middle name. |
| `gender` | `M`, `F` or `OTHER`. Any other value is ignored. |
| `email` | A valid email address. A malformed one fails the row. |
| `phone` | Stored exactly as written. |
| `address_line1`, `address_line2` | Mailing address lines. |
| `city` | City. |
| `parish` | Parish or region. |
| `postal_code` | Postal code. |
| `employment_status` | `EMPLOYED`, `SELF_EMPLOYED`, `UNEMPLOYED`, `RETIRED`, `STUDENT` or `OTHER`. Any other value is ignored. |
| `trn` | The member's tax ID (TRN in Jamaica). |
| `dl_number` | Driver's licence number. |

<Warning>
  If your CSV contains tax IDs, driver's licence or account numbers, delete it from your computer after the import. The values are encrypted once imported, but the file on your machine is plain text.
</Warning>

### Starter template

The upload step has a **Download a starter template** link: a CSV with the header row and one sample row to edit in place. Check the header includes `member_since` and add it if missing.

## Limits

| Limit | Value |
|---|---|
| Rows per file | 500 |
| File size | 1 MB |
| Committed imports | 5 per hour per person |

Split a larger file and import the pieces. A file that does not read as CSV is rejected whatever its extension.

## Import members

<Steps>
  <Step title="Upload the CSV">
    Drag the file onto the drop zone or browse for it, then click **Continue**. The file is virus-scanned, then every row is validated and each `cif` and `branch_code` is checked against your workspace. Nothing is created yet.

    A file is rejected outright, with the reason shown, when it is infected, empty, has a header but no rows, is over the row limit, is missing a required column, or cannot be read as CSV.
  </Step>
  <Step title="Review the preview">
    Every row shows a status, and the summary strip filters by it:

    - **Ready**: valid and will be created.
    - **Already a customer**: an active member with this `cif` already exists. A CIF that belonged to a deleted member can be reused.
    - **Duplicate in file**: the same `cif` appears in an earlier row.
    - **Invalid**: failed validation. The reason shows, for example `missing first_name`, `cu_account_number must be up to 16 digits`, `member_since cannot be in the future` or `branch_code does not exist in this workspace`.

    Only **Ready** rows are committed.
  </Step>
  <Step title="Commit the valid rows">
    Click **Create N members**. The file is checked against what you previewed, revalidated, and a member is created for every row still valid. The result step shows how many were created and lists any rows skipped, with a reason for each.
  </Step>
</Steps>

<Note>
  A row can change between preview and commit. If a colleague creates a member with the same `cif` in the meantime, that row is skipped and reported, and the rest of the batch still goes through.
</Note>

## After the import

Imported members start **Unverified** and need [KYC verification](/omnia/los/members/kyc-verification) before a loan can be submitted. Your credit union's required-fields rules are not applied on import. A member missing a required field shows the incomplete-record banner when opened. Each import, and each member it creates, is recorded in the audit trail.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Our old file now fails the header check. Why?">
    `cu_account_number` and `member_since` are required columns. Add both, filled from Core Banking, and upload again.
  </Accordion>
  <Accordion title="Can I import members without their Core Banking account number?">
    No. Every row needs it, the same as the New member form.
  </Accordion>
  <Accordion title="What happens to a CIF that already exists?">
    The row shows as **Already a customer** and is skipped. The existing member is not changed.
  </Accordion>
  <Accordion title="How many members can I import at once?">
    500 rows per file, up to 1 MB, and 5 committed imports per hour per person.
  </Accordion>
  <Accordion title="Are imported members verified?">
    No. They start **Unverified** and need KYC before a loan can be submitted.
  </Accordion>
</AccordionGroup>
