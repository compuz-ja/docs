The identity verification health screen shows which service answers your member identity checks and lets you test that each one responds.

Member identity checks confirm a member's tax ID and driver's licence against an outside identity service, such as your national identity service. This screen checks no member. It tells you which service each check is connected to and lets you send a test check to each. Use it after your identity service settings change, or when member checks misbehave and you need to know whether the service is reachable.

**Required permission:** **Manage workspace**, held by the Administrator.

Open **Administration → Settings → Identity Verifier**. The page is titled **Identity verifier health**.

## What the screen shows

### Configured providers

A chip for each check shows the service it uses:

- The tax ID chip, labelled **TRN** (the tax ID in Jamaica).
- **Driver's licence**, the licence check.
- **Recording wrapper active**, when your support team is recording traffic to diagnose a problem.

The chip color tells you the state:

- **Green**: connected to a live service.
- **Amber**: set up for a live service, but its credentials are missing, so the check has fallen back to a test service. Member checks are not reaching the real service.
- **Grey**: deliberately set to the test service, which gives fixed answers and checks nobody.

The motor-vehicle check used on vehicle loans is not tested here, so a green screen says nothing about it.

Your LOS support team connects and changes these services. The change takes effect without any downtime.

### Run a check

Click **Run health check** to send a test identity, not a real member, to each check. For each one you see:

- Whether it **responded** or **failed**.
- The **service** that answered.
- The **result**: Verified, Partial, Failed, or Manual review.
- How long it took, in milliseconds.

A summary line shows when the check ran and whether all providers responded ("All providers responded" or "One or more failed").

On a test service the test identity always comes back **Verified**. Any other result there means the connection itself is broken, not that a member failed.

<Warning>
  On a live service, each test is a real check that counts against that service's usage limits and fees. Run it to diagnose a problem, not on a schedule.
</Warning>

The test sends no member data and does not appear in the audit trail.

## When member checks fail

This screen tests the same services that member identity checks use. If members are failing checks unexpectedly, run the health check first. An amber chip, or a live service that does not respond, explains it. Send the result to your LOS support team.

To submit a member for checking and handle the results, see [KYC verification](/omnia/los/members/kyc-verification).
