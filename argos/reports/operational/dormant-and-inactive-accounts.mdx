## What it answers

What is sitting still, and for how long?

| | |
|---|---|
| Report key | `ops-dormancy` |
| Edition | Comply, tier 1 |
| Owner | Branch Manager |
| Capability | `reports.run` |
| Frequency | Monthly |
| Delivery | On demand |
| Modules | `DW09`, `DW19` |

## Parameters

| Parameter | Type | Required | Default |
|---|---|---|---|
| **As at** | date | Yes | `LAST_CLOSE` |
| **Minimum days inactive** | number | No | `90` |

## Reading a row

| Column | Type | Meaning |
|---|---|---|
| `inactivity_band` | text | Inactivity band |
| `branch_name` | text | Branch |
| `accounts` | integer | Accounts |
| `members` | integer | Members |
| `total_balance` | currency | Balance held |
| `average_balance` | currency | Average balance |
| `flagged_dormant` | integer | Flagged dormant |

<Note>
  Dormancy is measured on member-initiated activity. Interest postings do not reset the clock, which is the whole point.
</Note>

## Exports and evidence

Every run writes a row to the audit trail with the run identifier shown above, the parameters used, the row count and who ran it. The **CSV**, **XLSX**, **PDF** and **JSON** buttons export exactly the rows on screen, so an export and its audit entry always agree. **Definition** opens the report definition this page describes.
