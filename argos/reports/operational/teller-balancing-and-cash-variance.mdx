## What it answers

Did every teller balance?

| | |
|---|---|
| Report key | `ops-teller-balancing` |
| Edition | Comply, tier 1 |
| Owner | Branch Manager |
| Capability | `reports.run` |
| Frequency | Daily |
| Delivery | On demand |
| Modules | `DW09` |

## Parameters

| Parameter | Type | Required | Default |
|---|---|---|---|
| **From** | date | Yes | `PERIOD_MONTH_START` |
| **To** | date | Yes | `LAST_CLOSE` |
| **Unbalanced days only** | boolean | No | `False` |

## Reading a row

| Column | Type | Meaning |
|---|---|---|
| `business_date` | date | Date |
| `branch_name` | text | Branch |
| `teller_name` | text | Teller |
| `opening_float` | currency | Opening float |
| `cash_received` | currency | Received |
| `cash_paid` | currency | Paid |
| `closing_cash` | currency | Expected |
| `counted_cash` | currency | Counted |
| `variance` | currency | Variance |
| `transaction_count` | integer | Txns |
| `status` | text | Status |

<Note>
  An unbalanced teller day is an exception whether the variance is over or under. A surplus is not a good outcome.
</Note>

## Exports and evidence

Every run writes a row to the audit trail with the run identifier shown above, the parameters used, the row count and who ran it. The **CSV**, **XLSX**, **PDF** and **JSON** buttons export exactly the rows on screen, so an export and its audit entry always agree. **Definition** opens the report definition this page describes.
