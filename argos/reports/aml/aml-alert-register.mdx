## What it answers

Which alerts were raised in this period, and what happened to each one?

| | |
|---|---|
| Report key | `aml-alert-detail` |
| Edition | Comply, tier 1 |
| Owner | Compliance Officer |
| Capability | `reports.aml.run` |
| Delivery | On demand |
| Modules | `DW07` |

## Parameters

| Parameter | Type | Required | Default |
|---|---|---|---|
| **From** | date | Yes | `PERIOD_MONTH_START` |
| **To** | date | Yes | `LAST_CLOSE` |
| **Status** | select | No | `ALL` |
| **Minimum severity** | select | No | `ALL` |

**Status** offers **Every status**, **Open**, **Investigating**, **Escalated**, **STR filed**, **False positive**.

**Minimum severity** offers **Any**, **Medium and above**, **High and above**, **Critical only**.

## Reading a row

| Column | Type | Meaning |
|---|---|---|
| `alert_reference` | text | Alert |
| `raised_date` | date | Raised |
| `member_number` | text | Member |
| `member_name` | text | Name |
| `branch_name` | text | Branch |
| `scenario_name` | text | Scenario |
| `severity` | text | Severity |
| `risk_score` | integer | Score |
| `aggregate_amount` | currency | Value |
| `transaction_count` | integer | Txns |
| `status` | text | Status |
| `days_open` | integer | Days open |
| `str_reference` | text | STR ref |

<Note>
  An alert is not a suspicion. It is a rule firing. The disposition column is where judgement is recorded, and an alert closed as a false positive is evidence the rule was reviewed, not evidence it was wrong.
</Note>

## Exports and evidence

Every run writes a row to the audit trail with the run identifier shown above, the parameters used, the row count and who ran it. The **CSV**, **XLSX**, **PDF** and **JSON** buttons export exactly the rows on screen, so an export and its audit entry always agree. **Definition** opens the report definition this page describes.
