## What it answers

What matched a sanctions or watch list, and what was decided?

| | |
|---|---|
| Report key | `aml-screening-hits` |
| Edition | Comply, tier 1 |
| Owner | Compliance Officer |
| Capability | `reports.aml.run` |
| Frequency | Daily |
| Delivery | On demand |
| Modules | `DW07` |

## Parameters

| Parameter | Type | Required | Default |
|---|---|---|---|
| **From** | date | Yes | `PERIOD_MONTH_START` |
| **To** | date | Yes | `LAST_CLOSE` |
| **Matches only** | boolean | No | `True` |

## Reading a row

| Column | Type | Meaning |
|---|---|---|
| `list_name` | text | List |
| `screening_mode` | text | Mode |
| `screenings` | integer | Screenings |
| `matches` | integer | Matches |
| `hit_rate` | percent | Hit rate |
| `true_matches` | integer | True matches |
| `false_positives` | integer | False positives |
| `pending` | integer | Pending review |
| `avg_match_score` | number | Avg score |

<Note>
  Real-time onboarding hits and batch rescreening hits are separated because they carry different obligations. Do not total them.
</Note>

## Exports and evidence

Every run writes a row to the audit trail with the run identifier shown above, the parameters used, the row count and who ran it. The **CSV**, **XLSX**, **PDF** and **JSON** buttons export exactly the rows on screen, so an export and its audit entry always agree. **Definition** opens the report definition this page describes.
