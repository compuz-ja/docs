## What it answers

What do the institution's members actually look like?

| | |
|---|---|
| Report key | `mem-segmentation` |
| Edition | Understand, tier 2 |
| Owner | Executive |
| Capability | `reports.member.run` |
| Delivery | On demand |
| Modules | `DW10` |

## Parameters

| Parameter | Type | Required | Default |
|---|---|---|---|
| **Period** | month | Yes | `LAST_CLOSE_MONTH` |

## Reading a row

| Column | Type | Meaning |
|---|---|---|
| `segment` | text | Segment |
| `member_count` | integer | Members |
| `share_pct` | percent | Share |
| `avg_relationship_value` | currency | Avg relationship value |
| `total_deposits` | currency | Deposits |
| `total_loans` | currency | Loans |
| `avg_products_held` | number | Avg products |
| `digital_adoption_pct` | percent | Digital adoption |
| `delinquency_pct` | percent | Delinquency |
| `attrition_risk_high` | integer | High attrition risk |

## Exports and evidence

Every run writes a row to the audit trail with the run identifier shown above, the parameters used, the row count and who ran it. The **CSV**, **XLSX**, **PDF** and **JSON** buttons export exactly the rows on screen, so an export and its audit entry always agree. **Definition** opens the report definition this page describes.
