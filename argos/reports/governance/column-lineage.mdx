## What it answers

Where did this figure come from?

| | |
|---|---|
| Report key | `gov-lineage` |
| Edition | Comply, tier 1 |
| Owner | Data Steward |
| Capability | `data.lineage.view` |
| Delivery | On demand |
| Modules | `DW14` |

## Parameters

| Parameter | Type | Required | Default |
|---|---|---|---|
| **Starting layer** | select | No | `ALL` |
| **Object contains** | text | No | — |

**Starting layer** offers **Every layer**, **Source**, **Landing**, **Staging**, **Core**, **Mart**, **Semantic**.

## Reading a row

| Column | Type | Meaning |
|---|---|---|
| `from_layer` | text | From layer |
| `from_object` | text | From object |
| `from_column` | text | From column |
| `to_layer` | text | To layer |
| `to_object` | text | To object |
| `to_column` | text | To column |
| `transform_kind` | text | Transform |
| `transform_note` | text | Note |
| `model_name` | text | Model |

<Note>
  Every hop from a report column back to the source extract column. This is what answers an auditor asking how a number was produced without anyone opening the code.
</Note>

## Exports and evidence

Every run writes a row to the audit trail with the run identifier shown above, the parameters used, the row count and who ran it. The **CSV**, **XLSX**, **PDF** and **JSON** buttons export exactly the rows on screen, so an export and its audit entry always agree. **Definition** opens the report definition this page describes.
