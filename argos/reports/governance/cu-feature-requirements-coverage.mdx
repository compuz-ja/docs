## What it answers

Which requirements are covered, and by what evidence?

| | |
|---|---|
| Report key | `gov-requirements-coverage` |
| Edition | Comply, tier 1 |
| Owner | Report Developer |
| Capability | `governance.requirements.view` |
| Delivery | On demand |
| Modules | `DW14` |

## Parameters

| Parameter | Type | Required | Default |
|---|---|---|---|
| **Module** | select | No | `ALL` |
| **Coverage** | select | No | `ALL` |

**Coverage** offers **All requirements**, **Covered only**, **Not yet covered**.

## Reading a row

| Column | Type | Meaning |
|---|---|---|
| `req_id` | text | Req ID |
| `module` | text | Module |
| `sub_module` | text | Sub-module |
| `requirement` | text | Requirement |
| `report_count` | integer | Reports |
| `reports` | text | Reporting on this |

<Note>
  Coverage is mapped at module granularity, so every requirement in a module shows the same reports as evidence. That is honest at module level and coarse at line level.
</Note>

## Exports and evidence

Every run writes a row to the audit trail with the run identifier shown above, the parameters used, the row count and who ran it. The **CSV**, **XLSX**, **PDF** and **JSON** buttons export exactly the rows on screen, so an export and its audit entry always agree. **Definition** opens the report definition this page describes.
